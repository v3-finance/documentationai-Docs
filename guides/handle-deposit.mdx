description: >-

Входящие средства приходят ончейн, а Wallet Service следит за адресами и уведомляет V3 Custody вебхуком. Платформа зачисляет сумму в журнал и создаёт депозит. Здесь - как устроен контракт вебхука и как прочитать результат. Механику зачисления см. в [Журнале](/concepts/ledger).

<Callout kind="info" collapsed="false">
  Вебхук вызывает **Wallet Service**, а не вы. Со стороны интеграции вы обычно потребляете результат - депозиты, ленту и баланс.
</Callout>

Путь поступления - от ончейн-платежа до записи в ленте и балансе:

<MermaidDiagram chart={`
flowchart TD
ON["Ончейн-платёж на ваш адрес"] --> WS["Wallet Service следит за адресом"]
WS --> WH["POST /webhooks/wallet (TOPUP)"]
WH --> RT["Резолв токена по contract address"]
RT --> CR["Зачисление в журнал"]
CR --> DEP["Депозит создан"]
DEP --> HIST["Лента (direction=in) + available"]
DEP --> CP["Автосопоставление контрагенту"]
`} />

## Что понадобится

- Отслеживаемый адрес в Vault'е - см. [Сгенерировать адреса](/guides/generate-addresses).
- Токен доступа для чтения (см. [Аутентификацию](/authentication)).
- `code` Vault'а или id депозита для чтения результата.

## Шаг 1. Как приходит поступление

`POST /webhooks/wallet` принимает входящие on-chain события; сейчас обрабатывается только `TOPUP`. Токен резолвится из реестра по contract address, сумма зачисляется на адрес-получатель, и создаётся запись депозита.

Пример тела события:

```json
{
  "tx": {
    "network": "TRON",
    "asset": "TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t",
    "amount": "500.00",
    "toAddress": "TQ5kohbBSdorGoDBmCGUmDL7RUvNr75mBC",
    "txHash": "9f2c...e41a"
  }
}
```

`asset` - это contract address токена; по нему платформа находит токен в реестре.

<Callout kind="alert" collapsed="false">
  В демо-режиме вебхук без аутентификации и подписи (в проде планируется HMAC), а строгая схема тела не навязывается (внешний контракт, валидация внутри handler'а). Поля выше приведены для примера - точный контракт сверьте со [Справочником API](/api-reference).
</Callout>

## Шаг 2. Прочитайте поступление

Когда депозит создан, его детали доступны по id:

<CodeGroup show-lines="true">
  ```bash
  curl "[BASE_URL]/api/v1/vaults/acme-otc/deposits/DEPOSIT_ID" \
    -H "Authorization: Bearer $V3_TOKEN"
  ```

  ```javascript
  const res = await fetch("[BASE_URL]/api/v1/vaults/acme-otc/deposits/DEPOSIT_ID", {
    headers: { Authorization: `Bearer ${process.env.V3_TOKEN}` },
  });
  console.log(await res.json());
  ```

  ```python
  requests.get(
      "[BASE_URL]/api/v1/vaults/acme-otc/deposits/DEPOSIT_ID",
      headers={"Authorization": f"Bearer {os.environ['V3_TOKEN']}"},
  ).json()
  ```
</CodeGroup>

```json
{
  "id": "cmr3f41z20001psp7phmyapw3",
  "amountDecimal": "500.00",
  "token": "usdt",
  "toAddress": "TQ5kohbBSdorGoDBmCGUmDL7RUvNr75mBC",
  "amlStatus": null
}
```

| Поле                       | Что означает                               |
| -------------------------- | ------------------------------------------ |
| `id`                       | id депозита                                |
| `amountDecimal`            | сумма в человеческом формате               |
| `token`                    | символ токена                              |
| `toAddress`                | адрес-получатель                           |
| `amlStatus` / `amlDetails` | placeholder до появления automation engine |

## Шаг 3. Найдите поступления в ленте

Поступления попадают в вашу ленту активности и отражаются в балансе:

<CodeGroup show-lines="true">
  ```bash
  curl "[BASE_URL]/api/v1/vaults/acme-otc/history?direction=in" \
    -H "Authorization: Bearer $V3_TOKEN"
  ```

  ```javascript
  const res = await fetch(
    "[BASE_URL]/api/v1/vaults/acme-otc/history?direction=in",
    { headers: { Authorization: `Bearer ${process.env.V3_TOKEN}` } },
  );
  console.log(await res.json());
  ```

  ```python
  requests.get(
      "[BASE_URL]/api/v1/vaults/acme-otc/history",
      params={"direction": "in"},
      headers={"Authorization": f"Bearer {os.environ['V3_TOKEN']}"},
  ).json()
  ```
</CodeGroup>

Куда смотреть после зачисления:

| Что нужно          | Запрос                                                   |
| ------------------ | -------------------------------------------------------- |
| детали депозита    | `GET /api/v1/vaults/{code}/deposits/{id}`                |
| входящие в ленте   | `GET /api/v1/vaults/{code}/history?direction=in`         |
| обновлённый баланс | `GET /api/v1/vaults/{code}/balances` (вырос `available`) |

Поступление также автоматически сопоставляется контрагенту, если адрес-отправитель ему принадлежит.

<Expandable title="Глоссарий" default-open="false">
  - **TOPUP** - тип события вебхука о входящем поступлении (единственный обрабатываемый сейчас).
  - **Wallet Service** - внешний сервис, отслеживающий адреса и вызывающий вебхук.
  - **contract address** - ончейн-адрес контракта токена; по нему токен резолвится из реестра.
  - **депозит** - запись о зачисленном поступлении.
  - **amlStatus / amlDetails** - placeholder-поля под будущий automation engine.
</Expandable>

## Частые ошибки

| Симптом                    | Причина                                                      |
| -------------------------- | ------------------------------------------------------------ |
| депозит не появился        | Wallet Service не прислал `TOPUP` или адрес не отслеживается |
| токен не зачислен          | contract address нет в реестре - резолв не удался            |
| баланс не вырос            | смотрите на `available`, проверьте сеть и адрес-получатель   |
| нет привязки к контрагенту | адрес-отправитель не принадлежит ни одному контрагенту       |
| в проде вебхук отклонён    | не пройдёт HMAC-подпись (в демо её нет)                      |

## Готово, если

- событие `TOPUP` обработано, создан депозит;
- `GET .../deposits/{id}` возвращает `amountDecimal` и `token`;
- поступление видно в `history?direction=in`;
- `available` в `balances` вырос на сумму депозита.
