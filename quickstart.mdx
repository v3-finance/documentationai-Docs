In a few minutes you'll make your first calls to the V3 Custody REST API: find your Vault, check a balance, create an address, and send a transfer. All operations go through a single HTTP endpoint and follow the same rules as the web console.

<Callout kind="info" collapsed="false">
  The examples use the base URL `[BASE_URL]`, which is the address of your self‑hosted instance.
</Callout>

## Prerequisites

- The address of your V3 Custody instance, shown as `[BASE_URL]` in the examples.
- An access token for the `Authorization` header. See [Authentication](/authentication) for how to get one.
- Any HTTP client: `curl`, JavaScript, or Python.

## Set up your environment

Store the base URL and token in environment variables so you don't have to repeat them in every request.

<CodeGroup show-lines="true">
  ```bash
  export V3_BASE_URL="[BASE_URL]"
  export V3_TOKEN="YOUR_API_TOKEN"
  ```

  ```javascript
  const BASE_URL = process.env.V3_BASE_URL; // [BASE_URL]
  const TOKEN = process.env.V3_TOKEN;

  const headers = {
    Authorization: `Bearer ${TOKEN}`,
    "Content-Type": "application/json",
  };
  ```

  ```python
  import os, requests

  BASE_URL = os.environ["V3_BASE_URL"]  # [BASE_URL]
  TOKEN = os.environ["V3_TOKEN"]

  headers = {
      "Authorization": f"Bearer {TOKEN}",
      "Content-Type": "application/json",
  }
  ```
</CodeGroup>

<Callout kind="alert" collapsed="false">
  Never commit your token to a repository or hardcode it. Keep it in environment variables or a secrets manager.
</Callout>

## Step 1. Find your Vault

A Vault is your organization's address tree. Almost every route starts with its code (`code`, a slug). Get the list of Vaults available to you:

<CodeGroup show-lines="true">
  ```bash
  curl "$V3_BASE_URL/api/v1/vaults" \
    -H "Authorization: Bearer $V3_TOKEN"
  ```

  ```javascript
  const res = await fetch(`${BASE_URL}/api/v1/vaults`, { headers });
  const vaults = await res.json();
  console.log(vaults);
  ```

  ```python
  res = requests.get(f"{BASE_URL}/api/v1/vaults", headers=headers)
  vaults = res.json()
  print(vaults)
  ```
</CodeGroup>

```json
[
  {
    "id": "cmr3f41z20001psp7phmyapw3",
    "code": "demo_vault",
    "name": "Demo Vault",
    "lockedAt": null
  }
]
```

Note the `code`: from here on, it goes into every request as `{code}`.

## Step 2. Check your balance

In V3 Custody, a balance isn't stored as a separate number. It's computed from ledger entries and split into **available** (can be spent) and **reserved** (locked by pending transfers, but still yours).

<CodeGroup show-lines="true">
  ```bash
  curl "$V3_BASE_URL/api/v1/vaults/demo_vault/balances?summary=true" \
    -H "Authorization: Bearer $V3_TOKEN"
  ```

  ```javascript
  const res = await fetch(
    `${BASE_URL}/api/v1/vaults/demo_vault/balances?summary=true`,
    { headers },
  );
  console.log(await res.json());
  ```

  ```python
  res = requests.get(
      f"{BASE_URL}/api/v1/vaults/demo_vault/balances",
      params={"summary": "true"},
      headers=headers,
  )
  print(res.json())
  ```
</CodeGroup>

```json
{
  "vaultId": "cmr3f41z20001psp7phmyapw3",
  "totals": [
    { "token": "usdt", "available": "186000.00", "reserved": "24000.00" }
  ]
}
```

<ParamField query="summary" param-type="string" required="false" deprecated="false" show-location="true" enum="true,false">
  `true` returns only per-token totals, without the list of accounts.
</ParamField>

<ParamField query="addressId" param-type="string" required="false" deprecated="false" show-location="true">
  Balance of a specific address.
</ParamField>

<ParamField query="token" param-type="string" required="false" deprecated="false" show-location="true">
  Limit the result to a single token (for example, `usdt`).
</ParamField>

<Callout kind="tip" collapsed="false">
  Need a balance as of a past date? The separate endpoint `GET /api/v1/vaults/{code}/balances/as-of?at=...` reconstructs the position from entries recorded before the chosen point in time.
</Callout>

## Step 3. Create an address (optional)

A new address is ready to use from the first second. No activation or prefunding is needed, since Gas Station covers the fees. An address is defined by a network and a set of static derivation segments.

<CodeGroup show-lines="true">
  ```bash
  curl -X POST "$V3_BASE_URL/api/v1/vaults/demo_vault/addresses" \
    -H "Authorization: Bearer $V3_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "networkCode": "tron_network",
      "staticSegments": { "purpose": "invoices", "asset": "usdt" }
    }'
  ```

  ```javascript
  const res = await fetch(`${BASE_URL}/api/v1/vaults/demo_vault/addresses`, {
    method: "POST",
    headers,
    body: JSON.stringify({
      networkCode: "tron_network",
      staticSegments: { purpose: "invoices", asset: "usdt" },
    }),
  });
  console.log(await res.json());
  ```

  ```python
  res = requests.post(
      f"{BASE_URL}/api/v1/vaults/demo_vault/addresses",
      headers=headers,
      json={
          "networkCode": "tron_network",
          "staticSegments": {"purpose": "invoices", "asset": "usdt"},
      },
  )
  print(res.json())
  ```
</CodeGroup>

```json
{
  "id": "cmr3f41z20001psp7phmyapw3",
  "address": "TQ5kohbBSdorGoDBmCGUmDL7RUvNr75mBC",
  "network": "tron",
  "derivationPath": "m/44/195/0/0/1/1/0"
}
```

## Step 4. Send a transfer

A transfer isn't broadcast to the network right away. First the amount is reserved, then the request goes through the Policy Engine, which returns one of three outcomes: **allow**, **queue** (approval required), or **block**. Only after that do the MPC nodes sign the transaction.

Pass a unique `idempotencyKey`: retrying the request with the same key returns the transfer that was already created and never duplicates the payment.

<CodeGroup show-lines="true">
  ```bash
  curl -X POST "$V3_BASE_URL/api/v1/vaults/demo_vault/transfers" \
    -H "Authorization: Bearer $V3_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "fromAddressId": "cmr3f41z20001psp7phmyapw3",
      "toAddress": "TQ2m...p4rX",
      "token": "usdt",
      "amount": "1350.00",
      "idempotencyKey": "quickstart-transfer-001"
    }'
  ```

  ```javascript
  const res = await fetch(`${BASE_URL}/api/v1/vaults/demo_vault/transfers`, {
    method: "POST",
    headers,
    body: JSON.stringify({
      fromAddressId: "cmr3f41z20001psp7phmyapw3",
      toAddress: "TQ2m...p4rX",
      token: "usdt",
      amount: "1350.00",
      idempotencyKey: "quickstart-transfer-001",
    }),
  });
  console.log(await res.json());
  ```

  ```python
  res = requests.post(
      f"{BASE_URL}/api/v1/vaults/demo_vault/transfers",
      headers=headers,
      json={
          "fromAddressId": "cmr3f41z20001psp7phmyapw3",
          "toAddress": "TQ2m...p4rX",
          "token": "usdt",
          "amount": "1350.00",
          "idempotencyKey": "quickstart-transfer-001",
      },
  )
  print(res.json())
  ```
</CodeGroup>

<Callout kind="alert" collapsed="false">
  The request body fields shown here are for illustration only. For the exact, up-to-date list of parameters and formats, see the create transfer page in the [API Reference](/api-reference).
</Callout>

If the Policy Engine returns **queue**, the transfer waits for approval. You can see the approval request and its status via `GET /api/v1/vaults/{code}/approval-requests`. While the request is pending, the amount stays **reserved**; if it's rejected, the amount returns to **available**.
