V3 Custody is self-hosted: you deploy the platform in your own environment, so the base URL is the address of your instance. Throughout the documentation it appears as `[BASE_URL]`; replace it with your actual address.

How instance addresses are structured:

<MermaidDiagram chart={`

BU["[BASE_URL] — instance root"] --> API["/api/v1 — main prefix"]
BU --> WH["/webhooks/wallet — outside /api/v1"]

API --> TL["/evaluate, /policies, /invitations — top-level"]
`} />

## Base URL

`[BASE_URL]` is the root of your instance. It's used in every example (easy to spot by the square brackets and replace with a single search).

## Addressing scopes

Almost all endpoints live under `/api/v1`; webhooks are the exception:

| Scope        | Path pattern                          | Examples                                        |
| ------------ | ------------------------------------- | ----------------------------------------------- |
| vault-scoped | `[BASE_URL]/api/v1/vaults/{code}/...` | `balances`, `transfers`, `reports`, `addresses` |
| top-level    | `[BASE_URL]/api/v1/...`               | `evaluate`, `policies`, `invitations`           |
| webhooks     | `[BASE_URL]/webhooks/...`             | `webhooks/wallet` (`TOPUP`)                     |

Example paths:

```typescript
GET  [BASE_URL]/api/v1/vaults
GET  [BASE_URL]/api/v1/vaults/acme-otc/balances
POST [BASE_URL]/api/v1/vaults/acme-otc/transfers
POST [BASE_URL]/api/v1/evaluate
```

## Webhooks live outside `/api/v1`

The incoming Wallet Service webhook lives separately from the API prefix, at `[BASE_URL]/webhooks/wallet`. This is where Wallet Service sends its events (`TOPUP`). For details, see the [Handle an incoming deposit](/guides/handle-deposit) guide.

## Conventions in examples

In all examples, the base URL and token are stored in environment variables:

<CodeGroup show-lines="true">
  ```bash
  export V3_BASE_URL="[BASE_URL]"
  export V3_TOKEN="YOUR_API_TOKEN"
  ```

  ```javascript
  const BASE_URL = process.env.V3_BASE_URL; // [BASE_URL]
  const TOKEN = process.env.V3_TOKEN;
  ```

  ```python
  import os

  BASE_URL = os.environ["V3_BASE_URL"]  # [BASE_URL]
  TOKEN = os.environ["V3_TOKEN"]
  ```
</CodeGroup>

The token is passed in the `Authorization: Bearer <token>` header. See [Authentication](/authentication).

<Expandable title="Glossary" default-open="false">
  - **self-hosted**: the platform is deployed in your environment; the base URL is your instance's address.
  - **\[BASE\_URL]**: the placeholder for the instance root in examples.
  - **/api/v1**: the main API version prefix.
  - **vault-scoped**: endpoints tied to a specific Vault (`/vaults/{code}/...`).
  - **top-level**: endpoints outside the vault scope (`/evaluate`, `/policies`, `/invitations`).
  - **`{code}`**: a Vault is addressed in the path by its `code` (not by its id).
</Expandable>

## Common mistakes

| Symptom                        | Cause                                                                       |
| ------------------------------ | --------------------------------------------------------------------------- |
| `404` on every call            | the `/api/v1` prefix is missing                                             |
| webhook doesn't arrive         | it's being sent under `/api/v1`, but it lives outside the prefix, at `/webhooks/wallet` |
| Vault not found by path        | the path expects the `code`, but an id was passed                           |
| `[BASE_URL]` sent in a request | the placeholder wasn't replaced with the instance address                  |
| double `//` in the URL         | `BASE_URL` ends with a slash and the path starts with one                   |
