## Вход по magic-link

Вход выполняется по magic-link, а не по паролю:

- `POST /api/v1/auth/magic-link` — отправляет magic-link на email (через Cloudflare Email binding). Войти могут только существующие пользователи и приглашённые (с активным приглашением); регистрация без приглашения заблокирована hook'ом better-auth. После клика по ссылке пользователь редиректится на фронтенд (`FRONTEND_URL`).

<CodeGroup tabs="cURL,JavaScript,Python">
```bash
curl -X POST "[BASE_URL]/api/v1/auth/magic-link" \
  -H "Content-Type: application/json" \
  -d '{ "email": "trader@acme.com" }'
```
```javascript
await fetch("[BASE_URL]/api/v1/auth/magic-link", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email: "trader@acme.com" }),
});
```
```python
import requests

requests.post(
    "[BASE_URL]/api/v1/auth/magic-link",
    json={"email": "trader@acme.com"},
)
```
</CodeGroup>

## Способы предъявления: Bearer и cookie

Оба способа — одна и та же сессия better-auth, но разный транспорт:

| | Bearer | Cookie |
|--|--------|--------|
| для кого | сервисы, мобильные | веб-консоль |
| как передаётся | `Authorization: Bearer <токен>` | httpOnly-cookie, автоматически |
| доступ из JS | да (вы храните токен) | нет (httpOnly, по замыслу) |
| server↔server | да | нет |

## Ошибки аутентификации

Без валидного токена или сессии вернётся `401`:

```json
{
  "error": "Unauthorized",
  "message": "Authentication required. Please provide a valid API token",
  "code": 401
}
```

| Код | Когда | Значение |
|-----|-------|----------|
| `401` | нет валидного токена/сессии | не аутентифицирован — «кто вы» неизвестно |
| `403` | аутентифицирован, но нет прав | членство в группах не даёт действие (default-deny) |

Аутентифицированный, но недостаточно авторизованный запрос вернёт `403` — доступ определяется членством в группах (default-deny; без allow-политик действия запрещены).

## Модель доступа

Аутентификация отвечает «кто вы», доступ — «что вам можно». В V3 Custody права определяются членством в группах политик, отдельных «скоупов» у токена нет. Видимость по умолчанию изолирована: участник видит своё, администратор — весь Vault; расширяется через `visibility-grants`. Подробнее — на странице [Аутентификация](/authentication) и в гайде [Пригласить команду](/guides/invite-team).

## Частые ошибки

| Симптом | Причина |
|---------|---------|
| `401` хотя токен передан | истёк срок сессии или неверный формат заголовка `Authorization` |
| регистрация не проходит | нет активного приглашения — вход только для существующих/приглашённых |
| cookie не читается из JS | httpOnly по замыслу — для server↔server используйте Bearer |
| `403` у нового пользователя | не добавлен ни в одну группу (default-deny) |
| magic-link не приходит | проверьте email / Email binding; вход возможен только для приглашённых |
