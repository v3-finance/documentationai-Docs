Lists in V3 Custody use cursor-based **keyset pagination**: you page through results by passing the cursor from the previous page. Unlike offset pagination, keyset pagination is stable under inserts, so rows are never skipped or duplicated between pages.

<MermaidDiagram chart={`
flowchart TD
REQ["GET list?limit=N"] --> RESP["{ items, nextCursor }"]
RESP --> Q{"nextCursor present?"}
Q -->|yes| NEXT["GET ...?cursor=nextCursor"]
NEXT --> RESP
Q -->|no / empty| END["No more pages"]
`} />

## Keyset pagination

A list returns its items along with the cursor for the next page:

```json
{
  "items": [ ... ],
  "nextCursor": "eyJpZCI6..."
}
```

- `cursor`: pass the previous page's `nextCursor` here to get the next page.
- `limit`: the page size.
- When `nextCursor` is empty or missing, there are no more pages.

## Sorting

By default, lists are sorted newest first: descending by a time key, with `id` as a tiebreaker. The cursor follows the same order:

| List             | Sort key (descending) |
| ---------------- | --------------------- |
| ledger           | `postedAt`, `id`      |
| operations feed  | `createdAt`, `id`     |
| counterparties   | `createdAt`           |

## Common filters

The available set depends on the endpoint, but the same filters come up repeatedly:

| Filter                 | Meaning                                    | Where it's used                  |
| ---------------------- | ------------------------------------------ | -------------------------------- |
| `from` / `to`          | time window (by `createdAt` / `postedAt`)  | ledger, feed, counterparties     |
| `direction`            | `in` / `out`                               | operations feed                  |
| `token`                | limit to a token                           | balances, addresses, ledger      |
| `status`               | status                                     | approval requests, operations    |
| `search`               | substring                                  | addresses, counterparties        |
| `access=shared`        | only what's shared with you                | addresses                        |
| `mine` / `pendingMine` | mine / awaiting my vote                    | approval requests                |
| `userId`               | admin: whose activity to show              | lists with activity              |

<Callout kind="info" collapsed="false">
  Available filters vary by endpoint. See the page for the specific list in the [API Reference](/api-reference) for the exact set.
</Callout>

## Example: iterate through all pages

<CodeGroup show-lines="true">
  ```bash
  # a single page; for the next one, pass nextCursor as ?cursor=
  curl "[BASE_URL]/api/v1/vaults/acme-otc/history?direction=in&limit=100" \
    -H "Authorization: Bearer $V3_TOKEN"
  ```

  ```javascript
  let cursor;
  const all = [];
  do {
    const url = new URL("[BASE_URL]/api/v1/vaults/acme-otc/history");
    url.searchParams.set("direction", "in");
    url.searchParams.set("limit", "100");
    if (cursor) url.searchParams.set("cursor", cursor);

    const page = await fetch(url, {
      headers: { Authorization: `Bearer ${process.env.V3_TOKEN}` },
    }).then((r) => r.json());

    all.push(...page.items);
    cursor = page.nextCursor;
  } while (cursor);
  ```

  ```python
  cursor, items = None, []
  while True:
      params = {"direction": "in", "limit": 100}
      if cursor:
          params["cursor"] = cursor
      page = requests.get(
          "[BASE_URL]/api/v1/vaults/acme-otc/history",
          params=params,
          headers={"Authorization": f"Bearer {os.environ['V3_TOKEN']}"},
      ).json()
      items += page["items"]
      cursor = page.get("nextCursor")
      if not cursor:
          break
  ```
</CodeGroup>

<Expandable title="Glossary" default-open="false">
  - **keyset pagination**: paging by the previous page's cursor (stable under inserts, unlike offset).
  - **cursor**: the cursor of the requested page (the previous page's `nextCursor`).
  - **nextCursor**: the cursor of the next page; empty means the end of the list.
  - **limit**: the page size.
  - **tiebreaker**: `id`, which guarantees a deterministic order when time keys are equal.
</Expandable>

## Common mistakes

| Symptom                                | Cause                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| duplicates or gaps between pages       | you expected offset pagination; this is keyset, so page with the cursor        |
| infinite loop                          | `cursor` isn't updated from `nextCursor`                                        |
| cursor "doesn't work"                  | the `cursor` came from a different list or sort order; cursors aren't portable  |
| filter is ignored                      | this endpoint doesn't support the filter (see the API Reference)               |
| unexpected order                       | lists are sorted newest first (descending) by default                          |
